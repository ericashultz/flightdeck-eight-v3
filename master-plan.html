What this is

The structure we run to.

  • The operating system for the engagement. Not a pitch, the plan of record.
  • Every week has a recap, a plan, and a presentation. Nothing drifts between meetings.
  • Four gates, four written sign-offs. Each one unlocks the next phase.
  • Every deliverable has a defined done. Every dependency has an owner and a date.

Deliverable D1 · Phase 1 · accepted Jul 31

FLIGHT DECK Dashboard.

Acceptance criteria
  • →Homepage and Fundamental Pages deployed with the Supermarket role based layout.
  • →Three Behavior Pages deployed in SharePoint Online.
  • →Global navigation surfaces high frequency tools above static content.
  • →GE sign-off that priority tools are reachable in under two clicks.
Scope boundaries
  • →One hub site, not a multi-site rollout.
  • →Up to three layout revision rounds per page, then T&M.
  • →GE performs content migration; Bttr delivers structure.
  • →Inherits tenant permissions; no custom auth or SSO work.
Deliverable D2 · Phase 1 · accepted Jul 31

Template Library.

Acceptance criteria
  • →Library deployed with sort, search, and filter controls.
  • →Templates discoverable by role, function, and content type.
  • →Contextual Wingmate prompts surfaced alongside templates.
  • →GE sign-off on the directory information architecture.
Scope boundaries
  • →Directory UX only. No system audit or governance model.
  • →GE owns content and metadata inside templates.
  • →Up to three filter dimensions.
  • →Excel to SharePoint conversion not included.
Deliverable D3 · Phase 2 · accepted Oct 9

Wingmate Integration.

Acceptance criteria
  • →Prompt Library Page deployed in SharePoint Online.
  • →Prompts callable via single-click context action in template headers.
  • →Problem Solving prompt active with role aware handoff.
  • →Top-Performing Prompts panel on the Dashboard; pattern documented.
Scope boundaries
  • →Mechanism locked Week 9 (URL handoff or iframe via script editor).
  • →Up to nine prompts; GE authors prompts, Bttr does not.
  • →Surface-layer integration only; no Wingmate backend changes.
  • →Wingmate platform availability is outside Bttr control.
Deliverable D4 · Phase 2 · accepted Oct 9

Huddle Coach.

Acceptance criteria
  • →End to end capture to coaching application active in SharePoint.
  • →Automated rating and notes from Wingmate rendered in the UI.
  • →Suggested standard work surfaced when relevant.
  • →Historical database of ratings for trend and habit tracking.
Scope boundaries
  • →GE provides the maturity rubric. Blocking dependency.
  • →Capture via SharePoint form and upload; asynchronous, not real-time.
  • →Output is structured text; no generated video or audio.
  • →One facilitator workflow; more roles via change request.

Holding the line

How scope stays scope.

  • Revisions. Up to three design revision rounds per page. Beyond that runs on time and materials.
  • GE owns content. Migration, template contents, prompt authoring, and the maturity rubric sit with GE.
  • Surface layer only. Built in SharePoint via the script editor. No new platforms, no Wingmate backend changes, no external APIs.
  • Changes are written. New roles, added scope, or new workflows go through a change request, not a hallway ask.
