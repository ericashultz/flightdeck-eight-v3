Common questions — Common questions

EyebrowCommon questions↗ see on page
TextMy work is not repetitive. Does standard work apply? +↗ see on page
BodyYes. Standard work applies to any task that repeats at least once. Even knowledge work has sequences: how you structure a report, how you run a design review, how you hand off a drawing. You are not locking in a rigid script. You are capturing the best known approach so you have a baseline to improve from. The standard changes when you find a better way.↗ see on page
TextHow detailed does the standard need to be? +↗ see on page
BodyDetailed enough that someone new could follow it on day one without asking questions. That is the test. Most first drafts are too long. Aim for the steps that actually affect quality, safety, or timing. Everything else can live in a supporting note or link.↗ see on page
TextWhat is the difference between Manufacturing SW, Non-Manufacturing SW, and Leader SW? +↗ see on page
BodyManufacturing Standard Work captures physical steps at a workstation with cycle times and takt time. Non-Manufacturing Standard Work captures sequences for office, service, or engineering tasks where the work is information-based, not physical. Leader Standard Work captures the daily and weekly routines a team leader follows to observe, develop, and sustain a system. If you are not on the shop floor, start with Non-Manufacturing.↗ see on page
TextHow often should I update a standard? +↗ see on page
BodyUpdate it whenever the process changes, whenever you find a better way, or whenever training someone reveals a gap. For stable processes, a monthly review is enough. A standard that has not been reviewed in six months is almost certainly out of date.↗ see on page

TextPhysical board or digital? +↗ see on page
BodyPhysical boards are faster to update, easier to see at a glance, and require no login or load time. They are the default for shop-floor teams who share a space. Digital boards work well for distributed teams or when the board needs to feed a tier-2 or tier-3 review automatically. Start physical if you are new to daily management. You can migrate to digital once the habit is set and the metrics are stable.↗ see on page
TextWhat metrics go on a tier 1 board? +↗ see on page
BodyTier 1 boards track the four to six SQDC metrics the team directly controls: Safety (near misses, incidents), Quality (first-pass yield, defects), Delivery (units to schedule, on-time shipment), and Cost (overtime, scrap rate). Every metric should have a daily target and a result the team can update themselves. Avoid metrics that require a manager to retrieve the data. If the team cannot update it in real time, it does not belong on a tier-1 board.↗ see on page
TextHow long should the stand-up be? +↗ see on page
BodyTen minutes. Review SQDC top to bottom: green items get a nod, any non-green item gets a named owner and a one-line note. Problems that need more than two minutes to discuss go to the parking lot and are addressed after the stand-up, not during it. If your stand-ups regularly run past ten minutes, the board is probably doing too much work that should happen before or after the meeting.↗ see on page
TextWhat is the difference between tier 1, 2, and 3? +↗ see on page
BodyTier 1 is the team or cell level: daily stand-up, SQDC metrics, problems resolved by the team lead within the shift. Tier 2 is the value-stream or department level: issues escalated from tier 1 that need cross-team ownership or more than a day to resolve. Tier 3 is the site or business-unit level: systemic problems, capacity constraints, or anything that requires executive or cross-site action. The tiers are connected: an unresolved tier-1 miss should reach tier 2 within 48 hours, and an unresolved tier-2 issue should reach tier 3 within the week.↗ see on page

TextIs 5S just cleaning? +↗ see on page
BodyNo. Cleaning is one of the five S — Shine — and even that is not primarily about cleanliness. Shine is a systematic inspection: cleaning is the method, finding abnormalities is the goal. The other four S address what stays in an area, where things live, what the standard looks like, and how to keep it. Together they create a workplace where problems become visible before they become failures.↗ see on page
TextHow is 5S different in an office? +↗ see on page
BodyThe five S apply exactly the same way, but the targets are different. Sort means archiving or deleting files and clearing desk clutter, not removing unused fixtures. Set in order means a consistent shared drive structure and naming convention, not shadow boards. Shine means a regular review of the digital workspace for outdated documents and broken links. The discipline is identical; the surface it runs on is information instead of tools and materials.↗ see on page
TextHow often should we audit? +↗ see on page
BodyWeekly for most production and lab areas. Monthly for office and shared service areas where the workspace changes more slowly. The cadence matters less than the consistency. A team that misses audits for two weeks will find that 5S has faded. Wingmate can set the schedule and send reminders so the audit runs without prompting.↗ see on page
TextWhat is a red tag? +↗ see on page
BodyA red tag is a physical or digital label placed on any item whose need in the area is uncertain. It is a question, not a verdict. Once tagged, the team has a defined window — typically 48 hours — to decide: keep, relocate, return to stock, or remove. Everything that stays gets a permanent home. Everything that leaves is logged in the Red Tag Log so the decision is visible and reversible if needed.↗ see on page

Common questions — Common questions

EyebrowCommon questions↗ see on page
TextHow long should a daily review be? +↗ see on page
BodyFifteen minutes is the target. The standing rule is: if it runs past 15 minutes, something is being solved in the review instead of assigned. The review surfaces problems and assigns owners. Solving happens offline. If your daily review is running 30 minutes consistently, the agenda has drifted from its purpose. Audit it, cut the section that is becoming a problem-solving session, and assign that work outside the cadence.↗ see on page
TextWhat is the difference between a tier 1 and a tier 3 review? +↗ see on page
BodyTier 1 is the team-level daily review at the board. It covers the work that happened yesterday and today. Tier 2 is the value-stream weekly review that aggregates the tier-1 results and drives decisions at the value-stream level. Tier 3 is the site or business-unit monthly review that connects the weekly results to the annual plan. Problems that cannot be solved at tier 1 escalate to tier 2. Problems that cannot be solved at tier 2 escalate to tier 3. Each tier has a different owner, a different time horizon, and a different purpose.↗ see on page
TextWhat goes on the agenda? +↗ see on page
BodyFor a daily review: SQDC metrics, misses against standard, and action assignment. For a weekly review: open actions from last week, SQDC trend review by cell, escalations that need a decision this week, and one top priority for the value stream. For a monthly review: 90-day SQDC trends, escalation resolution, resource and priority decisions, and the connection to the annual plan. The standing rule is: anything on the agenda that is not driving a decision or surfacing a problem should be removed. The agenda is not a status report. It is the operating system for the team.↗ see on page
TextHow do actions get closed? +↗ see on page
BodyAn action closes when the owner brings proof of completion to the next review. Proof is specific: a changed process, a resolved defect, a decision recorded. "Worked on it" is not a close. If an action cannot close by its due date, the owner escalates it before the next review with a clear ask: what decision or resource is needed to unblock it. Actions that slip without escalation signal that the cadence is not being held. The discipline of closing actions is what separates a structured operating cadence from a status meeting.↗ see on page

TextWhat is the difference between value-add and non-value-add time? +↗ see on page
BodyValue-add time is any step the customer would pay for if they knew about it: forming a part, writing a design, completing an analysis. Non-value-add time is everything else: waiting in a queue, being batched, moving between buildings, sitting in an inbox. Most processes are under 10% value-add when mapped honestly. That number is not a failure; it is the opportunity. The goal of VSM is to make the ratio visible so you know where to improve.↗ see on page
TextHow detailed should the map be? +↗ see on page
BodyDetailed enough to see the constraint and the largest waste. A value stream map is not a process map of every micro-step. It operates at the level of major process boxes, not individual tasks within a step. If you find yourself drawing twenty boxes for a single manufacturing cell, you have gone too deep. A first map should fit on one large sheet of paper and take one focused session to draw. Go deeper only if the analysis requires it.↗ see on page
TextCurrent state or future state first? +↗ see on page
BodyCurrent state first, always. A future state drawn without a current-state map is a solution looking for a problem. You cannot know what to fix until you see what is actually happening. Walk the flow, draw it as it runs today, quantify the waste, name the constraint, and only then draw the future state. Teams that skip the current state tend to improve the wrong step or set targets with no basis in the data.↗ see on page
TextWho should be in the mapping session? +↗ see on page
BodyThe people who run the flow, not the people who manage it. A mapping session with only managers produces a map of what managers think happens. You need the operator who runs the grind cell, the analyst who processes the contract, the engineer who owns the review gate. Aim for a small cross-functional group (four to eight people) who collectively touch every step. Managers set the scope and attend the out-brief; the people who do the work draw the map.↗ see on page

TextCan two people own an action? +↗ see on page
BodyNo. Shared ownership reliably produces no ownership. When two people share an action, each assumes the other is handling it. Name the one person who will be asked at the next review whether the action is done. That is the owner. If the work genuinely requires two people, split the action into two: one per owner, each with its own due date.↗ see on page
TextHow often should we review the plan? +↗ see on page
BodyMatch the cadence to the velocity of the work. Daily stand-up actions should be reviewed at the next stand-up. Kaizen follow-through actions should be reviewed at least weekly, at the tier-2 board. Project actions with milestones longer than a week should have a weekly status check. The rule of thumb: if an action can go two days without anyone noticing it slipped, your cadence is too slow.↗ see on page
TextWhat makes a good action? +↗ see on page
BodyA good action has three properties. First, it starts with a verb and names the deliverable: "Update the setup checklist," not "Setup checklist." Second, it has a clear done signal that anyone on the team can verify, not just the owner. Third, it belongs to one person on a specific date. If you cannot write those three things in one row of a table, the action needs more definition before it goes on a plan.↗ see on page
TextHow is this different from a project plan? +↗ see on page
BodyA project plan captures milestones, dependencies, and a schedule across weeks or months. An action plan captures the concrete steps that move you toward one outcome, each owned and dated. Most project plans need an action plan inside each milestone. Most action plans are not full project plans. Use the Improvement or Daily type when the work is a follow-through on a solved problem or a stand-up capture. Use the Project type when you have cross-functional milestones and dependencies that need explicit tracking across more than two or three weeks.↗ see on page

Common questions — Common questions

EyebrowCommon questions↗ see on page
TextWhat is the difference between push and pull? +↗ see on page
BodyPush means producing based on a schedule or forecast regardless of what downstream actually needs. Pull means producing only what downstream consumed, triggered by a signal from the customer or the next step. Push systems build inventory because the schedule is never perfectly accurate. Pull systems cap inventory because nothing is produced without a signal. Most operations are a mix; the goal is to increase the proportion of pull wherever demand is visible enough to signal.↗ see on page
TextWhat is a kanban? +↗ see on page
BodyKanban is a visual signal that authorizes production or replenishment. The signal can be a card, an empty bin, a marked floor location, or a digital flag. The key property is that nothing is produced or moved without the signal. Kanban sizing sets the minimum (reorder point) and maximum (cap) for each item. When inventory drops to the minimum, the signal triggers replenishment up to the maximum. The math is simple: minimum equals demand during replenishment lead time plus safety stock. Maximum equals minimum plus one replenishment quantity.↗ see on page
TextDo we need flow before pull? +↗ see on page
BodyStable flow makes pull more reliable, but you do not need perfect flow to start. Many teams implement a basic pull signal while flow is still being improved. The sequence that works best is: identify the constraint, stabilize it, then connect flow around it, then size the pull signal. Trying to set kanban quantities when flow is highly variable produces unreliable signals. The practical test is whether you can predict demand well enough to calculate a reorder point. If yes, start with pull. If demand is too erratic, stabilize the process first.↗ see on page
TextDoes pull work in an office? +↗ see on page
BodyYes. Transactional pull is the same principle applied to information work. Instead of a bin, the signal is a WIP cap: each person or step can hold only a defined number of items in progress. When an item is completed and passed downstream, the next item is pulled in. The pull board makes the cap and the state of each item visible. The result is shorter lead time because batches stop accumulating and context switching falls. Claims processing, engineering reviews, contract approvals, and close cycles have all benefited from transactional pull boards.↗ see on page
