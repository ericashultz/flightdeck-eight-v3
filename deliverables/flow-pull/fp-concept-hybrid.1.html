The Evolution from Push to Flow

The evolution
from Push
to Flow with pull
to Flow
Phase 1

Understand the value stream, level load and pace work to rate of customer demand (takt time)

  • Calculate the takt time
  • Identify areas where cycle time > takt time (process constraints)
  • Identify and remove process wastes
  • Balance process steps between what we can do (cycle time) to what the customer wants (takt time)
Phase 2

Create flow

  • Choose families of products or processes that work together
  • Define process and material flow and identify waste
  • Focus problem solving in combining processes and implement one piece flow of material
Phase 3

Incorporate pull

  • Where you can’t combine processes or implement one piece flow, implement standardized pull
Phase 4

Level load and Linearity

  • Level load the time taken in each process step to optimize cycle time to takt time
  • Implement accountability across the entire P&L to achieve linearity (sales, development, transactional business processes)

Common questions

Frequently Asked Questions

What is the difference between push and pull? +

Push means producing based on a schedule or forecast regardless of what downstream actually needs. Pull means producing only what downstream consumed, triggered by a signal from the customer or the next step. Push systems build inventory because the schedule is never perfectly accurate. Pull systems cap inventory because nothing is produced without a signal. Most operations are a mix; the goal is to increase the proportion of pull wherever demand is visible enough to signal.

What is a kanban? +

Kanban is a visual signal that authorizes production or replenishment. The signal can be a card, an empty bin, a marked floor location, or a digital flag. The key property is that nothing is produced or moved without the signal. Kanban sizing sets the minimum (reorder point) and maximum (cap) for each item. When inventory drops to the minimum, the signal triggers replenishment up to the maximum. The math is simple: minimum equals demand during replenishment lead time plus safety stock. Maximum equals minimum plus one replenishment quantity.

Do we need flow before pull? +

Stable flow makes pull more reliable, but you do not need perfect flow to start. Many teams implement a basic pull signal while flow is still being improved. The sequence that works best is: identify the constraint, stabilize it, then connect flow around it, then size the pull signal. Trying to set kanban quantities when flow is highly variable produces unreliable signals. The practical test is whether you can predict demand well enough to calculate a reorder point. If yes, start with pull. If demand is too erratic, stabilize the process first.

Does pull work in an office? +

Yes. Transactional pull is the same principle applied to information work. Instead of a bin, the signal is a Work In-Process (WIP) cap: each person or step can hold only a defined number of items in progress. When an item is completed and passed downstream, the next item is pulled in. The pull board makes the cap and the state of each item visible. The result is shorter lead time because batches stop accumulating and context switching falls. Claims processing, engineering reviews, contract approvals, and close cycles have all benefited from transactional pull boards.
